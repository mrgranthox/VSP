Section 6
Page Layout Patterns
Six reusable layout patterns cover all 48 pages. Identify the pattern, apply it, fill with the correct content.
1
List Page
Pages 7,11,16,18,20,21,25,42,43 and more
PageHeader (title + count + actions)
FilterBar (search + selects + reset)
TabsLine (status filter tabs with counts)
DataTable (sortable cols + row hover + actions dropdown)
Pagination (showing X-Y of Z + prev/next)
2
Detail Page (2-Column)
Pages 8,12,17,19,22,26 and more
HeroCard (avatar + key stats + action buttons full-width)
TabsLine (Profile | Services | Bookings | Reviews | etc.)
Left 60%: main content (description, timeline, thread)
Right 40%: metadata sidebar (linked entities, actions, stats)
3
Dashboard / Analytics
Pages 4, 30, 31, 32, 33, 44
DateRangePicker (top-right, 7d/30d/90d/custom)
StatCards row (4–6 cards, grid-cols-4 or 6)
Charts row (2 cols: recharts LineChart + BarChart)
Charts row 2 (2 cols: DonutChart + secondary)
Supporting table (top items, leaderboard, or log)
4
Split-Panel (Verification / Review)
Pages 14, 24, 40, 48
Left 45%: subject profile / content preview
Right 55%: document viewer / evidence / actions
Decision bar (full-width bottom): action buttons + MFA field
Both panels scroll independently
5
Card Grid (Queue / Flags / Cities)
Pages 13, 15, 36, 37, 38, 39
PageHeader (title + count badge + primary action)
Filter chips or tabs
grid-cols-2 (or 3) card layout
Each card: left-border accent colour + icon + stats + action buttons
6
Compose / Form Page
Pages 35, 40, 41, 45, 46, 47
Left 60%: form fields (React Hook Form + Zod validation)
Right 40%: live preview / summary / history
Sticky footer: Cancel + Submit (disabled until valid + MFA if needed)
MFA field in amber box above submit when required

Master Prompt Template
// PASTE WITH: 00_ARCHITECTURE.md + relevant module context file

Generate the [PAGE NAME] page for VSP Admin.

DESIGN SYSTEM:
- Font: Plus Jakarta Sans (all UI) + JetBrains Mono (IDs, tokens)
- Sidebar: bg-[#0A0F1E] w-60 fixed — already built, import from @/components/admin/Sidebar
- Top bar: bg-white h-16 sticky — import from @/components/admin/TopBar
- Content area: bg-[#F0F4FF] p-6
- Primary: #1D4ED8 | Success: #10B981 | Warning: #F59E0B | Danger: #EF4444
- Use StatusBadge component from @/components/admin/ui/StatusBadge
- Use DataTable component from @/components/admin/ui/DataTable

LAYOUT PATTERN: [Pattern 1–6 from design system reference]

PAGE CONTENT:
[Describe the specific sections, columns, data shown]

API:
- Endpoint: [e.g. GET /api/v1/admin/workers]
- Hook: useQuery with queryKey ['admin-workers', filters]
- Show skeleton loader while isLoading=true
- Show error state with retry if isError=true

PERMISSION GUARD:
- Wrap with: <RequirePermission permission="WORKER_VIEW">

EMPTY STATE:
- Show: [Icon + "No workers found" + clear filters button]

Use shadcn/ui components. TypeScript. No inline styles — Tailwind classes only.
Example — Workers List (Page 11)
Generate the Workers List admin page for VSP Admin.
LAYOUT PATTERN: Pattern 1 (List Page)
CONTENT: PageHeader "Workers" + count chip + "Export CSV" button
FilterBar: search by name/trade + Status select + Trade select + City select + Featured toggle
TabsLine: All | Submitted (12) | Under Review (6) | Approved | Rejected
DataTable cols: checkbox | Avatar+Name+email | Trade badges | City | StatusBadge |
  Rating (★ 4.8) | Jobs | Response% | Joined | Actions dropdown
Row with status=SUBMITTED gets inline "Review →" amber chip instead of actions dropdown
API: GET /api/v1/admin/workers — useAdminWorkers hook — WORKER_VIEW permission
Empty: HardHat icon + "No workers match your filters" + Reset button
Example — Verification Review (Page 14)
Generate the Worker Verification Review page for VSP Admin.
LAYOUT PATTERN: Pattern 4 (Split Panel)
LEFT 45%: Worker avatar + name + headline + trade badges + bio (scrollable)
  Service area + stats row (portfolio items, certs)
RIGHT 55%: Document viewer — tab per document, PDF/image frame,
  toolbar (zoom/rotate/download), document type label + file info
DECISION BAR (full width, fixed bottom): Notes textarea left +
  "✓ Approve" (green btn) + "✗ Reject" (red btn) right +
  MFA field (amber box) under buttons
API: GET /admin/workers/:id/verification-documents (signed URLs)
  POST /admin/workers/:id/verify | POST /admin/workers/:id/reject-verification
PERMISSION: WORKER_VERIFY + mfaVerified=true required
